# Unified Nightjar experience — October 15 update

This updates the existing installation. Keep the same project directory, Compose project, database volumes, media directory and `deploy/.env`. No database reset is required.

## What changed

- `/learn` is the student entry point: registration, login, recovery, account/profile, courses, lessons, discussions, reviews and progress.
- Registration accepts name, email, password and confirmation. It creates only a Student account, applies native Frappe password validation plus a 12-character minimum, and does not depend on SMTP.
- Password changes require the current password. Forgotten-password links still require outgoing email. The administrator can create student accounts and set student passwords from **Students** without SMTP.
- Login uses Frappe's login manager, including native account lockout and two-factor challenge handling. The built-in `Administrator` username is accepted.
- Course ratings and written reviews now appear on course pages. Enrolled students can post one review per course. The instructor can post or replace their response. Administrators can delete a review or instructor response.
- Lesson discussions allow student and instructor replies. Administrator removal replaces the comment text with a removal notice so existing replies retain their context.
- Staff see Teaching studio, Payments and Students. Student navigation does not expose these tools. `/app` remains the advanced administration area.
- Ordinary student `/lms` entry links redirect into Nightjar. Course/lesson deep links are mapped when resolvable. Native resource frames remain available inside the lesson.
- Rich lesson blocks reuse the native renderer within the Nightjar lesson. A new revision-checked LMS patch supplies a content-only activity entry point. A real multiple-choice quiz was rendered and submitted inside it during browser testing. Nested assignment/programming frames retain their existing native implementation.
- Refreshed dark surfaces, blue actions, typography, course cards and responsive account/review/student-management screens follow the supplied design extraction files.

## Update your running installation

**Superseded by [REPAIR-2026-10-15.md](REPAIR-2026-10-15.md). Use the complete updater there; the manual steps below are retained for historical context.**

Run commands from your existing `nightjar-learning` folder.

1. Back up:

   ```bash
   docker compose --env-file deploy/.env -f deploy/compose.yaml exec app bash -lc 'cd /home/frappe/work/bench && bench --site nightjar.localhost backup --with-files'
   ```

   Copy important backups outside the Docker volume. Do not continue if backup reports a failure.

2. Stop the application:

   ```bash
   docker compose --env-file deploy/.env -f deploy/compose.yaml stop app
   ```

3. Extract the new ZIP into a separate temporary folder. Merge these updated items into your existing project, replacing old versions:

   - `nightjar_learning/`, `frontend/`
   - `deploy/init.sh`, `deploy/apply_upstream_patches.py`, `deploy/patches/`
   - `README.md`, `docs/`, `scripts/`, `tests/`

   Preserve `deploy/.env`, your existing Compose file, private media and any unrelated local edits. Review conflicts if you customized the same source files. Do not use `down -v`.

4. Restart:

   ```bash
   docker compose --env-file deploy/.env -f deploy/compose.yaml up -d app
   docker compose --env-file deploy/.env -f deploy/compose.yaml logs -f app
   ```

   This runs migrations for review-response fields and rebuilds native/custom assets. Wait for **Starting development services** and the web-server ready message. The native build is substantial; allow it to finish. `Ctrl+C` leaves the log viewer without stopping the detached app. A revision/patch-conflict error requires review; do not remove the version guard.

5. Hard-refresh and open `http://nightjar.localhost:8000/learn`.

## One account for the owner/instructor

Keep one personal **System User** with **Course Creator**, **Moderator**, and **System Manager** roles. Set these once in the full User form under `/app/user`, using the built-in Administrator. Add your personal account as the instructor on your courses so your name appears publicly. Keep the built-in Administrator for recovery.

The **Students** page intentionally creates students only; it cannot promote a student to staff. Staff permissions remain in advanced settings. You do not need separate instructor and administrator logins.

## First checks after updating

1. In a private browser window, register a student at `/learn#view=signup` and sign in with the chosen password.
2. Enroll in a free course, complete a lesson, post a comment and a course review.
3. With your owner account, reply to the review and moderate a lesson comment.
4. Open Students, create a student and set a password. Check that it works in a separate browser session.
5. Submit a payment request as a student, approve it as owner, then open the paid course as that student.
6. Confirm your real course resources render and your private videos play on the devices you intend to support.

## Delivery limits

- This is a tested development update, not a production security certification. It has not been run on your Docker host.
- Registration does not verify ownership of the email address. Add verification before relying on email identity for a public launch. SMTP delivery and live two-factor delivery were not exercised; native server-side policy remains in use.
- Advanced quiz timing/proctoring, assignments, programming exercises, SCORM, certificates and every native block variant have not received comprehensive end-to-end testing in the embedded renderer. Their inner presentation may retain native styling. Batch/live-class administration is still native; this update focuses on self-paced course learning.
- Reviews and lesson discussions currently load up to 200 posts per course/lesson. Large communities need pagination. Each review supports one replaceable instructor response.
- Real-device Safari/Firefox, long playback renewal and mobile fullscreen watermark behavior remain to be checked. AES-HLS access control cannot prevent screen recording or copying by an authorized viewer.
- No public deployment was performed.
