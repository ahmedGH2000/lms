# Repair incomplete updates — release 2026.10.15.2

The reported errors (`accounts.login` / `accounts.register` missing and no
`nightjar_learning.community` module) mean the running Python backend does not
contain the code the interface expects. They are not invalid-password errors.
The distributed previous ZIP contains those methods. The logs establish a
frontend/backend mismatch, but cannot distinguish an incomplete copy, the wrong
mounted folder, an old installed app, or a process that was not restarted.

The earlier Redis MISCONF failure is separate. The latest supplied log shows
catalog requests succeeding. Do not delete the database or recreate its volume.

## Apply the complete repair

1. Download this release and extract it into a **separate** folder, for example:
   `~/Downloads/nightjar-repair/nightjar-learning`.
   Verify this folder contains `release-manifest.json` and `deploy/update-local.sh`.
2. Keep the existing installation running for the backup. In your terminal:

   ```bash
   cd ~/Downloads/Compressed/nightjar-learning
   bash ~/Downloads/nightjar-repair/nightjar-learning/deploy/update-local.sh "$PWD"
   ```

   Adjust only the new extracted path if you chose another location. Run the
   updater from the **new** extracted release, passing the **existing** project
   folder. Do not extract over the existing folder first.

   The updater checks the complete package and the actual Compose source mount;
   backs up the database and uploads; copies the site backups outside Docker;
   stops only the app; backs up replaced source files; copies the complete app;
   and recreates the app container. It preserves `deploy/.env`, the existing
   Compose configuration, media and all database volumes. Backups are in a
   sibling `nightjar-learning-before-update-…` folder printed by the script.
   A backup/preflight error stops before application files are copied. Do not
   bypass a failed backup. If the app is already stopped, start it using the
   existing Compose configuration before running this backup-based updater.

3. Follow startup:

   ```bash
   docker compose --env-file deploy/.env -f deploy/compose.yaml logs -f app
   ```

   Wait for the release check, `Checking release APIs, database and Redis writes`,
   and `Starting development services`, then the web-server ready message. First
   native asset builds may take time. Ctrl+C exits this log viewer only.

4. Verify the installed release:

   ```bash
   docker compose --env-file deploy/.env -f deploy/compose.yaml exec -T app bash -lc 'cd /home/frappe/work/bench && bench --site nightjar.localhost execute nightjar_learning.deployment.check'
   ```

   Expect release `2026.10.15.2`, `api_methods: 27`, and `database`, `redis_write`
   and `review_schema` all `ok`. This resolves and checks every custom method
   used by the frontend; it does not create users or change passwords. It makes
   one temporary Redis write, with an expiry, to detect the earlier MISCONF case.
   Copy the final error if any check fails; do not reset the database.

5. Open `http://nightjar.localhost:8000/learn` and hard-refresh (Ctrl+Shift+R).
   Test signup in a private window, login, course filters, and a review/discussion.

## What this repair changes

- Startup verifies source and bundled assets against the release manifest before
  copying, and checks imports/whitelisting from the installed app before serving.
- The updater verifies the existing Compose mount and startup command, preventing
  a successful-looking update to a folder the running app does not use.
- Frontend entry filenames include a content hash, preventing cached old code
  from being reused after a successful update. Lazy modules use the same entry.
- A backend/interface contract check blocks incompatible forms with a clear
  update message, rather than presenting forms that call unavailable methods.
- Missing API errors are explained without exposing Python method tracebacks in
  account forms. Other server failures show a service-unavailable message.
- Catalog load failures show a retry state; they no longer claim there are zero
  courses. Old filter responses cannot overwrite a newer response. Retry clears
  the error. Search, all three difficulty values, empty results and clearing
  filters have focused browser coverage.

## Developer notes and limits

The manifest is a completeness/mixed-version check, not a cryptographic publisher
signature. For intentional application edits, review and build them, then run
`python3 deploy/verify_release.py . --build`. Do not regenerate it to conceal a
missing-file error. Compose and the environment template are operator-owned and
are intentionally outside the hash set.

The updater is tested with real shell/Python file operations and simulated Docker
commands, including successful copying and failure-before-copy paths. Docker is
not available in the assistant environment. Real Frappe/MariaDB/Redis and Chromium
checks are separate evidence. This cannot certify every feature or your machine;
email delivery, physical devices and the advanced activities listed in
`UPDATE-2026-10-15.md` remain outstanding. No public deployment was performed.
