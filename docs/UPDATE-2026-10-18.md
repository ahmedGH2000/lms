# Update Nightjar Learning — 2026.10.18.1

Use the **new downloaded folder** to update your **existing running project**. You do not need to replace individual files or reinstall Frappe.

1. Extract this ZIP into a separate folder. Open a terminal inside its inner `nightjar-learning` folder, the one containing `deploy` and `frontend`.
2. Keep your existing Nightjar containers running. From that new folder run:

```bash
bash deploy/update-local.sh "/home/bogiboii/Downloads/Compressed/nightjar-learning"
```

3. After it reports “Update started”, view startup progress:

```bash
cd "/home/bogiboii/Downloads/Compressed/nightjar-learning"
docker compose --env-file deploy/.env -f deploy/compose.yaml logs -f app
```

Wait for release `2026.10.18.1` to be verified and `Starting development services`. Press Ctrl+C to leave the log view; this does not stop Nightjar. Refresh the browser.

The updater verifies the download, backs up the database and uploaded files, exports that backup next to your existing folder, saves replaced source files, then restarts the app. It includes the local MariaDB backup TLS fix. Your `.env`, Compose settings, private media, and database volumes stay in place. A failed backup stops the update before app files are copied. No `docker compose down -v` or database reset is needed.

If an error appears, stop there and share the last error lines. Keep the printed backup directory.

## Where to go

- Students: `http://127.0.0.1:8000/learn`
- Instructors/administrators: `http://127.0.0.1:8000/lms`
- Review enrollment requests: `http://127.0.0.1:8000/lms/payment-requests`

Desktop LMS has a **Payment requests** sidebar link. On mobile, open **You → Payment requests**. Staff also have a **Student view** link.

Payment details are required (3–140 characters). A student may attach one JPG, PNG, or plain PDF up to 10 MB. Receipts are private; authorized users download them from the request. Review notes are required for approval, rejection, and revocation. Only administrators or the course’s assigned instructors can review. A Moderator role alone does not grant all-course payment rights.

Approving grants enrollment; revoking removes that enrollment. Rejected/revoked requests remain as history, and the student may submit a new request. A pending request cannot be replaced by submitting again. Payment verification remains manual: an uploaded receipt does not itself prove payment.

## After the update

Sign out and sign back in to check the new landing page. Try one test student request with text and an optional receipt, then approve it from the course instructor account. Check that another instructor cannot see that request, and that the student can open a lesson (including any embedded activity). Existing requests need no conversion and can still be reviewed.

The package includes automated checks, but this environment cannot run your Docker installation. The first startup performs the real schema migration and dependency checks; let it finish before judging the update.
